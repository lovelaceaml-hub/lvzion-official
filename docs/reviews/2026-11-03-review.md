## 6. What belongs in the cloud rather than on the Mac

- **CI added on this branch:** `.github/workflows/typecheck.yml` runs the type check on pushes to `main` and on PRs. `.github/workflows/full-suite.yml` is manual dispatch only, and runs only when `full_suite_approved` (default `false`) is ticked. The original recommendation was:
  - an automatic type check on every push or PR (`npm ci --ignore-scripts && npm run typecheck`, Node 24);
  - a manual-dispatch workflow with a `full_suite_approved` input that defaults to `false`, for `npm test`, `npm run test:db` and `npm run test:browser`, as AGENTS.md requires.
  - This moves the Playwright and PGlite runs off the laptop. GitHub-hosted runners are free for normal private-repo usage within the plan quota; confirm the quota before relying on it.
- **Race tests:** `scripts/test-morning-prayer-races.mjs:9` and `scripts/gospel-planning/test-races.mjs:11` default to Homebrew PostgreSQL. A CI Postgres service container would run them the same way. `LVZ_POSTGRES_BIN` already allows a different path.
- **Integration stack:** `tests/integration/start-stack.mjs` and `start-worship-stack.mjs` need local Postgres, PostgREST, Auth and SMTP. These suit a manually dispatched CI job, or a cloud session.
- **Design sweep:** `scripts/design-sweep.mjs:58` uses an installed Chrome. Playwright's bundled Chromium in CI would work.
- **Mac-only script:** `scripts/configure-signup-email.mjs:4` reads a Supabase token from the macOS Keychain. This is fine as a one-time operator step. For cloud use, read the token from an environment variable or a CI secret.
